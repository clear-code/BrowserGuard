# BrowserGuardとは

BrowserGuard は、Microsoft Edge の使われ方を組織の方針に沿って制限し、
その操作を証跡として記録するための Edge 用拡張機能です。

■ 本書で「■」は補足・注意事項を表します。

## 主な機能

BrowserGuard は以下の 7 つの機能で構成されます。
いずれも既定では無効であり、設定ファイルで個別に有効化します。

| 機能 | 内容 |
| --- | --- |
| 監査ログ（NetLogger） | URL アクセス・ページの閲覧・アップロード・ダウンロード・印刷を記録します。記録先はこの端末上のファイルと、収集サーバーへの送信の、片方または両方を選べます。 |
| アップロード制御（UploadGuard） | アップロードしてよいローカルファイルを、拡張子とパスで絞り込みます。禁止された場合はアップロードを中止し、警告を表示します。 |
| 設定ページの遮断（SettingPageFilter） | `edge://settings` などの設定ページを開けなくします。 |
| 起動時プログラム実行（StartupLauncher） | ブラウザーの起動に合わせて、指定されたプログラムを実行します。 |
| 使用時間の制限（UsageTimeLimit） | 連続して使用できる時間と、使用を許可する時間帯を制限します。超過時は警告するか、ブラウザーを終了します。 |
| タブ数の上限（TabCountLimit） | 同時に開けるタブの数を制限します。超過分は自動的に閉じます。 |
| アップロードファイルの控え（UploadFileBridge） | アップロードされたファイルの控えを、何が外に出たかの証跡として指定の場所に複製します。 |

## システム要件

### クライアント端末

* 64 ビット版の Windows
  * インストーラーは 64 ビット環境でのみ実行できます。
* Microsoft Edge（Chromium 版）
* インストール時に管理者権限

■ ネイティブメッセージングホストは .NET 8 の自己完結型として発行されるため、
  .NET ランタイムを別途インストールする必要はありません。

### 動作時の権限

インストールは管理者権限で行いますが、動作時のネイティブメッセージングホストは
Edge の子プロセスとして、ログオンしているユーザーの権限で動作します。
監査ログの保存先やアップロードファイルの控えの保存先には、
そのユーザーが書き込める場所を指定してください。

## ソフトウェアの構成

BrowserGuard は以下の 3 つで構成されます。

| コンポーネント | 役割 |
| --- | --- |
| Edge 拡張機能 | ブラウザーの動作に介入し、制限と記録を行います。Manifest V3 のサービスワーカーとして動作します。 |
| ネイティブメッセージングホスト | 拡張機能からは行えない処理（設定ファイルの読み込み、ファイルの複製、警告ダイアログの表示、外部プログラムの実行、ログのファイル出力と送信）を担当します。 |
| 設定ファイル | 全機能の動作を決める 1 つの JSON ファイルです。 |

各コンポーネントの関係は以下の通りです。

```
   ┌──────────────────────────── Microsoft Edge ────────────────────────────┐
   │                                                                        │
   │   ┌────────────────────┐                                               │
   │   │  BrowserGuard      │                                               │
   │   │  拡張機能          │                                               │
   │   │  (service worker)  │                                               │
   │   └─────────┬──────────┘                                               │
   │             │ ネイティブメッセージング (標準入出力)                    │
   └─────────────┼──────────────────────────────────────────────────────────┘
                 │
      ┌──────────┴───────────┐        ┌──────────────────────┐
      │  BrowserGuard.exe    │───────▶│  BrowserGuard.json   │
      │  (ホスト)            │  読込  │  (設定ファイル)      │
      └──────────┬───────────┘        └──────────────────────┘
                 │
      ┌──────────┴──────────┬────────────────┬────────────────────┐
      ▼                     ▼                ▼                    ▼
  監査ログ             収集サーバー     アップロード         起動時に実行する
  (netlog.jsonl)       (HTTP POST)      ファイルの控え       プログラム
```

動作の流れは以下の通りです。

1. Edge が拡張機能を読み込み、サービスワーカーを起動する。
2. 拡張機能がネイティブメッセージングホストを起動し、設定を要求する。
3. ホストがレジストリから設定ファイルの位置を得て、内容を読み込み、拡張機能へ返す。
4. 拡張機能が設定に従って動作する。
5. ファイルの複製やダイアログの表示など、拡張機能では行えない処理は、
   その都度ホストに依頼する。

### 拡張機能とホストのやり取り

ホストへのメッセージは、1 文字のコマンドと空白に続けて引数を並べた形式です。
トラブルシューティングの際、ホストのログにはこの内容が記録されます。

| コマンド | 内容 | 呼び出し方 |
| --- | --- | --- |
| `C` | 設定ファイルの読み込み | メッセージごとにホストを起動 |
| `W` | 警告ダイアログの表示 | メッセージごとにホストを起動 |
| `S` | 起動時プログラムの実行 | メッセージごとにホストを起動 |
| `U` | アップロードファイルの控えの作成 | メッセージごとにホストを起動 |
| `L` | 監査ログのエントリ | 接続を保ったまま送り続ける |

■ 監査ログは要求ごとに発生するため、`L` だけは接続を保つ方式（ポート）を使います。
  ホストのプロセスは、その接続が続く間 1 つだけ動作します。
  他のコマンドはメッセージのたびにホストのプロセスが起動し、応答を返して終了します。

## 配布ファイル

| ファイル | 役割 |
| --- | --- |
| `BrowserGuardSetup-<バージョン>.exe` | Windows 用インストーラー。拡張機能・ホスト・設定ファイルを配置します。 |
| `BrowserGuardSetup-<バージョン>.msi` | 上記インストーラーを内包した MSI パッケージ。MSI 形式しか受け付けない配布基盤で使用します。 |
| `parameter-sheet.xlsm` | パラメータシート。設定内容を記録・管理し、設定ファイルを出力します。 |
| `parameter-sheet-default.xlsm` | パラメータシートの配布時のデフォルト値。パラメータシートの値を変更しており、デフォルト値を参照したい場合に使用します。 |

## 設定の保持と反映のメカニズム

BrowserGuard の動作を指定するには、設定ファイル（`BrowserGuard.json`）を使用します。

■ **ユーザーが設定を変更するための画面はありません。**
  管理者が配布した設定ファイルの内容が、そのまま全ユーザーの動作になります。

設定は以下の要領で読み込まれ、動作に反映されます。

1. 拡張機能のサービスワーカーが起動し、ホストへ設定を要求する。
2. ホストがレジストリ `HKLM\SOFTWARE\BrowserGuard` の `ConfigFile` 値を読み、
   そのパスの設定ファイルを読み込む。
3. 拡張機能は、受け取った設定をサービスワーカーが動作している間は保持し、読み直さない。
4. サービスワーカーは待機状態になると停止し、次のイベントで復帰する。
   その際に設定を読み直す。

■ 上記 4 の通り、多くの場合は Edge を再起動しなくても設定変更が反映されます。
  ただし反映の時期はサービスワーカーの停止・復帰に依存するため、
  **確実に反映させるには Edge を再起動してください。**

### 設定ファイルが読めない場合の動作

| 状況 | 動作 |
| --- | --- |
| レジストリに `ConfigFile` が無い | ホストはすべての機能を無効として扱います。 |
| `ConfigFile` が指すファイルが無い、または JSON として壊れている | ホストがエラーを返します。拡張機能は組み込みの既定値で動作するため、いずれの制限も働きません。 |

いずれの場合も、ブラウザーは通常どおり使用できます。
BrowserGuard が「止まっているのに気付かない」状態を避けるため、
展開後は「動作の確認」の手順で有効性を確認してください。

# 検証環境での導入

ここでは、本番展開に先立って 1 台の端末に導入し、設定内容を決定するまでの手順を示します。

以下の順番で進めます。

1. インストーラーを実行する。
2. 拡張機能を Edge に登録する。
3. 設定ファイルを編集し、動作を確認する。
4. 本番展開用の設定ファイルを作成する。

## インストール

■ インストーラーは開始時に `msedge.exe` と `BrowserGuard.exe` を強制終了します。
  実行前に、保存していない作業がないことを確認してください。

1. `BrowserGuardSetup-<バージョン>.exe` を管理者権限で実行します。
2. タスクの選択画面で「拡張機能を Edge のポリシーに登録して自動的にインストールする」
   にチェックを入れます。
   * 検証環境では、この方法が最も手数が少なくて済みます。
   * 組織全体への展開ではグループポリシーで管理するため、本番ではチェックを外します。
3. インストールを完了します。

### 配置されるもの

インストール先（既定では `%ProgramFiles%\BrowserGuard`）に以下が配置されます。

| パス | 内容 |
| --- | --- |
| `BrowserGuard.json` | 設定ファイル |
| `BrowserGuardHost\BrowserGuard.exe` | ネイティブメッセージングホスト |
| `BrowserGuardHost\edge.json` | ホストマニフェスト |
| `BrowserGuardExtension\BrowserGuardEdge.crx` | 拡張機能 |
| `BrowserGuardExtension\manifest.xml` | 更新マニフェスト |

■ 設定ファイルは `onlyifdoesntexist` 指定で配置されるため、
  すでに存在する場合は上書きされません。バージョンアップ時に設定が保持されます。

### 登録されるレジストリ

いずれも文字列型（`REG_SZ`）です。

`HKLM\SOFTWARE\BrowserGuard`

| 値の名前 | 内容 |
| --- | --- |
| `Path` | インストール先（末尾に `\` を含む） |
| `ClientType` | 空文字列 |
| `Version` | バージョン |
| `Configfile` | 設定ファイルのパス |
| `ExtensionExecfile` | ホストの実行ファイルのパス |
| `ExtensionSettingsRegistered` | インストーラー自身がポリシーを登録した場合のみ `1` |

`HKLM\SOFTWARE\Microsoft\Edge\NativeMessagingHosts\com.clear_code.browser_guard`

* 既定値がホストマニフェスト（`edge.json`）のパスを指します。

■ 設定ファイルの位置を変えたい場合は、`Configfile` の値を書き換えてください。
  ホストはこの値だけを見ます。

\newpage

## 拡張機能の登録

crx を配置しただけでは Edge は拡張機能をインストールしません。
Edge のポリシー `ExtensionSettings` への登録が別途必要です。

インストール時にタスクにチェックを入れた場合、インストーラーが以下を登録します。

```
HKLM\SOFTWARE\Policies\Microsoft\Edge
  ExtensionSettings (REG_SZ) =
    {"<拡張機能ID>":{"installation_mode":"force_installed",
     "update_url":"file:///<インストール先>/BrowserGuardExtension/manifest.xml",
     "override_update_url":true}}
```

■ `ExtensionInstallForcelist` ではなく `ExtensionSettings` を使うのは、
  `ExtensionInstallForcelist` の `update_url` が初回インストールにしか使われないためです。
  更新時には拡張機能自身の `manifest.json` の `update_url` が参照されますが、
  自己ホストのビルドにはそれがありません。
  `override_update_url` を指定した `ExtensionSettings` であれば、更新時にもこの URL が使われます。

■ `ExtensionSettings` は全拡張機能をひとつの JSON 値で表します。
  インストーラーは既存の内容を読み込んだうえで、この拡張機能の項目だけを追加・削除します。
  他の拡張機能の設定は保持されます。

## 動作の確認

1. Edge を起動します。
2. `edge://extensions` を開きます。
   * BrowserGuard が一覧にあり、ポリシーによってインストールされた旨が表示されること。
3. `edge://policy` を開きます。
   * `ExtensionSettings` に BrowserGuard の項目が含まれること。
4. ホストのログ（`%APPDATA%\BrowserGuard\BrowserGuard.log`）を開きます。
   * `Command: load config` の行があること。
     拡張機能がホストと通信し、設定を読めていることを表します。

■ ポリシーで強制インストールされた拡張機能は、既定では開発者ツールを開けません。
  拡張機能側のログを見る必要がある場合は「ログとトラブルシューティング」をご参照ください。

## 設定の調整

設定ファイルを編集し、必要な機能を有効にします。
書式は「設定ファイルの書式」を、記入用の様式は「パラメータシート」をご参照ください。

変更を反映させる手順は以下の通りです。

1. 設定ファイルを保存する。
2. Edge を再起動する。

## 本番展開用の設定ファイルの作成

検証で決定した内容をパラメータシート（`parameter-sheet.xlsm`）に記入し、
「エクスポート」シートのボタンから設定ファイルを出力します。
出力された `BrowserGuard.json` を、次章の手順で組織全体へ配布します。

■ パラメータシートを使わず、設定ファイルを直接編集しても構いません。
  パラメータシートは、設定内容を文書として管理し、記入誤りを防ぐための様式です。

# 組織全体への展開

## 展開の全体像

以下の 3 つを各端末へ配布します。

1. BrowserGuard 本体（インストーラーのサイレント実行、または MSI パッケージ）
2. 拡張機能のポリシー登録（グループポリシー）
3. 設定ファイル（グループポリシーによるファイル配布）

■ 1 は exe と MSI のどちらでも結果は同じです。
  配布基盤が MSI 形式を要求する場合（グループポリシーの「ソフトウェアのインストール」など）に
  MSI を使用してください。

■ 2 と 3 をグループポリシーで管理することを標準としています。
  インストーラーによるレジストリへの直接書き込みは、
  グループポリシーが構成されている環境では `gpupdate` のたびに上書きされるため、
  本番展開では使用しません。

## インストーラーのサイレント実行

資産管理ツール、Intune、スタートアップスクリプトなどから、以下を管理者権限で実行します。

```
BrowserGuardSetup-<バージョン>.exe /VERYSILENT
```

この場合、拡張機能のポリシー登録は行われません。
グループポリシーを使わず、インストーラーに登録させる場合のみ、以下のように指定します。

```
BrowserGuardSetup-<バージョン>.exe /VERYSILENT /TASKS="extensionpolicy"
```

■ インストーラーは開始時に `msedge.exe` を強制終了します。
  業務時間中に配布すると、ユーザーの作業中のタブが失われます。
  ログオン時や再起動時など、Edge が動作していない時点で実行してください。

## MSI パッケージによる配布

Intune やグループポリシーのソフトウェアインストールなど、
**MSI 形式しか受け付けない配布基盤**を使用する場合は、MSI パッケージを配布します。

```
msiexec /i BrowserGuardSetup-<バージョン>.msi /qn
```

MSI は上記のインストーラー exe を内包しており、インストール時に一時フォルダーへ展開して
サイレント実行します。配置される内容は exe を直接実行した場合と同じです。

拡張機能のポリシー登録を併せて行う場合は、`INNO_SETUP_ARGS` で指定します。

```
msiexec /i BrowserGuardSetup-<バージョン>.msi /qn INNO_SETUP_ARGS="/TASKS=extensionpolicy"
```

■ MSI 自体は「プログラムと機能」に表示されません。
  一覧に表示されるのは内包されたインストーラーの「BrowserGuard」の項目のみです。
  二重に表示されることを避けるための意図的な設定です。

■ バージョンアップは、新しい MSI をそのままインストールすれば置き換わります。
  事前に旧バージョンをアンインストールする必要はありません。

## 拡張機能のポリシー登録

以下の作業は、ドメインコントローラー上またはドメインコントローラーを操作可能な端末上で、
システム管理者が管理者ユーザーアカウントで実施します。

1. グループポリシー管理コンソールを起動します。
2. BrowserGuard を使用する対象の OU にリンクされる GPO を作成します。
   ここでは `BrowserGuardPolicy` という名前で作成したと仮定します。
3. 作成した GPO を右クリックし「編集」を選択します。
4. 「コンピューターの構成」→「ポリシー」→「管理用テンプレート」
   →「Microsoft Edge」→「拡張機能」
   →「拡張機能の管理設定を構成する」を開きます。
   * Edge の管理用テンプレート（ADMX）が導入されている必要があります。
5. 「有効」を選択し、以下の JSON を 1 行で入力します。

```json
{"ddniogodiahgpmfkljajobgkaecabnif":
 {"installation_mode":"force_installed",
  "update_url":"file:///C:/Program Files/BrowserGuard/BrowserGuardExtension/manifest.xml",
  "override_update_url":true}}
```

* `update_url` はインストール先に合わせて読み替えます。
  区切りは `\` ではなく `/` を使い、空白は `%20` に置き換えます。

6. グループポリシー管理ツールを閉じます。

■ 拡張機能 ID（`ddniogodiahgpmfkljajobgkaecabnif`）は署名鍵から決まります。
  配布された crx と ID が食い違う場合、拡張機能はインストールされません。
  実際にインストールされた ID は `edge://extensions` で確認できます。

■ 他の拡張機能もこのポリシーで管理している場合は、
  同じ JSON オブジェクト内にそれぞれの項目を並べてください。
  このポリシーは全拡張機能をひとつの値で表すため、
  BrowserGuard の項目だけを別のポリシー設定として追加することはできません。

\newpage

## 設定ファイルの配布

各端末の設定ファイルを、グループポリシーのファイル配布で置き換えます。

以下の作業は、ドメインコントローラー上またはドメインコントローラーを操作可能な端末上で、
システム管理者が管理者ユーザーアカウントで実施します。

1. 全端末からアクセス可能なファイル配布用サーバー上に、
   一般ユーザー権限で読み取り可能なフォルダーを作成します。
   ここでは、コンピューター名が `fileserver` である Windows ファイル共有サーバー上に、
   以下の共有フォルダーを作成したと仮定します。
   * `\\fileserver\BrowserGuard`
2. 配布する `BrowserGuard.json` を、1 で作成したフォルダーにコピーします。
   * `\\fileserver\BrowserGuard\BrowserGuard.json`
3. 配置したファイルの「プロパティ」を開き、「セキュリティ」タブで、
   「Everyone」で読み取り可能な状態になっていることを確認します。
4. グループポリシー管理コンソールを起動し、
   「拡張機能のポリシー登録」で作成した GPO を編集します。
5. 「コンピューターの構成」→「設定」→「Windows の設定」→「ファイル」を選択します。
   * ■ 「ユーザーの構成」ではなく、必ず「コンピューターの構成」を使用してください。
     設定ファイルの配置先は `%ProgramFiles%` 配下であり、ユーザー権限では書き込めません。
6. 「ファイル」を右クリックし「新規作成」から「ファイル」を選択して、
   以下の内容で項目を作成します。
   * アクション：「置換」を選択。
   * ソースファイル：`\\fileserver\BrowserGuard\BrowserGuard.json`
   * ターゲットファイル：`C:\Program Files\BrowserGuard\BrowserGuard.json`
   * 属性：「読み取り専用」のみにチェック。
7. グループポリシー管理ツールを閉じます。

以上により、対象の端末で設定ファイルが自動的に配置・更新されるようになります。

### 設定ファイルの保護

■ **インストーラーはインストール先フォルダーに `Users` の変更権限を付与します。**
  そのため、既定の状態では一般ユーザーが `BrowserGuard.json` を書き換えたり
  削除したりできます。設定を確実に強制する必要がある場合は、
  上記手順 6 の「読み取り専用」属性に加えて、
  配布後に以下のようなコマンドでアクセス権を制限してください。

```
icacls "C:\Program Files\BrowserGuard\BrowserGuard.json" /inheritance:r ^
  /grant *S-1-5-32-544:F *S-1-5-18:F *S-1-5-32-545:R
```

* `*S-1-5-32-544` は Administrators、`*S-1-5-18` は SYSTEM、
  `*S-1-5-32-545` は Users を表す既知の SID です。
  言語環境に依存しないよう、グループ名ではなく SID で指定しています。

■ ホストの実行ファイル（`BrowserGuard.exe`）とホストマニフェスト（`edge.json`）については、
  インストーラーが継承を切って一般ユーザーの変更権限を外しています。
  保護が必要なのは設定ファイルです。

\newpage


# 運用手順

## 設定の変更

設定ファイルを更新し、各端末へ再配布します。
グループポリシーで配布している場合、対象端末での `gpupdate` または再起動によって反映されます。

反映の確認は以下で行います。

1. 端末上の `BrowserGuard.json` の内容が更新されていること。
2. Edge を再起動すること。
3. ホストのログに `Command: load config` の行が新たに記録されること。

## 監査ログの取り扱い

監査ログの既定の保存先は、ユーザーごとに分かれています。

```
%LocalAppData%\BrowserGuard\netlog\
```

■ ユーザーごとに分かれているのは、1 台の端末を複数人が使う構成（AVD など）で、
  1 つのファイルに混ざったり、互いの記録を読めてしまったりすることを避けるためです。
  ローミングプロファイルに含まれない `LocalAppData` を使うのも、
  数か月分の記録をネットワーク越しに持ち回らないためです。

そのため、**端末上の監査ログは記録の正本ではありません。**
証跡として集約する場合は、収集サーバーへの送信（`Sender`）を有効にしてください。
設定は「監査ログ（NetLogger）」をご参照ください。

保存先を共有フォルダーに変更する場合は、
`%MACHINENAME%` や `%USER%` を使ってユーザーごと・端末ごとにフォルダーを分けてください。
同じフォルダーに複数の端末から書き込むと、記録が混ざります。

## バージョンアップ

新しいバージョンのインストーラーを、初回と同じ手順で実行します。
設定ファイルは上書きされないため、設定は保持されます。

### 拡張機能の更新が反映されない場合

強制インストールされた拡張機能は、**Edge が更新チェックを実行したときにだけ**
新しいビルドに入れ替わります。Edge は起動直後ではなく数分後にチェックし、
以降は数時間おきになるため、再起動しただけでは古いビルドが動き続けることがあります。

すぐに反映させるには、対象の端末で以下を行います。

1. `edge://extensions` を開く。
2. 「開発者モード」をオンにする。
3. 「更新」を押す。

反映されたかどうかは、`edge://extensions` に表示されるバージョンで判断できます。

## アンインストール

「設定 > アプリ > インストールされているアプリ」（または「プログラムと機能」）から
BrowserGuard をアンインストールします。
サイレント実行する場合は、インストール先の `unins000.exe` に `/VERYSILENT` を指定します。

```
"C:\Program Files\BrowserGuard\unins000.exe" /VERYSILENT
```

MSI パッケージで導入した場合は、MSI の削除でも同じ結果になります。

```
msiexec /x BrowserGuardSetup-<バージョン>.msi /qn
```

■ どちらか一方を削除すれば、もう一方も併せて削除されます。
  MSI を削除すると内包されたインストーラーがアンインストールされ、
  「プログラムと機能」から BrowserGuard を削除すると MSI の登録も削除されます。
  片方だけが残ることはありません。

アンインストール時の挙動は以下の通りです。

| 対象 | 挙動 |
| --- | --- |
| `HKLM\SOFTWARE\BrowserGuard` | 削除されます。 |
| ネイティブメッセージングホストの登録 | 削除されます。 |
| `ExtensionSettings` の BrowserGuard の項目 | **インストーラー自身が登録した場合のみ**削除されます。 |
| 監査ログ | 削除されません。 |
| アップロードファイルの控え | 削除されません。 |

■ ポリシーの項目は、`HKLM\SOFTWARE\BrowserGuard` の `ExtensionSettingsRegistered` が
  `1` の場合にのみ削除されます。手動で設定した項目や、
  グループポリシー由来の項目は残ります。
  グループポリシーで配布している場合は、GPO 側の設定も併せて削除してください。

■ 監査ログと控えは証跡であるため、製品を削除しても残ります。
  不要な場合は別途削除してください。

\newpage


# 設定ファイルの書式

## ファイルの位置と形式

設定ファイルの位置は、レジストリ `HKLM\SOFTWARE\BrowserGuard` の `Configfile` 値が指す先です。
インストーラーの既定では `C:\Program Files\BrowserGuard\BrowserGuard.json` となります。

* 文字エンコーディングは UTF-8 です。BOM の有無は問いません。
* JSON 形式で記載します。
* プロパティ名の大文字・小文字は区別されません。
* 記述されていない項目は、既定値として扱われます。

## 全体の構成

設定ファイルは、機能ごとのオブジェクトを並べたひとつの JSON オブジェクトです。

```json
{
  "NetLogger":         { ... },
  "UploadGuard":       { ... },
  "SettingPageFilter": { ... },
  "StartupLauncher":   { ... },
  "UsageTimeLimit":    { ... },
  "TabCountLimit":     { ... },
  "UploadFileBridge":  { ... }
}
```

いずれの機能も `Enabled` を持ちます。
`Enabled` が `false` の場合、その機能の他の設定はすべて無視されます。

■ 以降の表の「既定値」は、**そのパラメータを記述しなかった場合に使われる値**です。

\newpage

## 監査ログ（NetLogger）

ブラウザーの操作を、1 行 1 JSON の監査ログとして記録します。
記録先は、この端末上のファイル（`LocalFile`）と収集サーバーへの送信（`Sender`）です。
両方を無効にした場合、記録は行われません。

```json
"NetLogger": {
  "Enabled": true,
  "UrlAccess": false,
  "Browsing": true,
  "Upload": true,
  "Download": true,
  "Print": true,
  "LocalFile": {
    "Enabled": true,
    "Directory": "",
    "MaxDays": 30,
    "MaxSizeMB": 0
  },
  "Sender": {
    "Enabled": true,
    "Endpoint": "https://collector.example.jp/netlog",
    "Spool": {
      "Enabled": true,
      "MaxSizeMB": 10,
      "Retry": {
        "Enabled": true,
        "IntervalMinutes": 5
      }
    }
  }
}
```

| パラメータ | データ型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `Enabled` | 真偽値 | `false` | この機能を有効にする |
| `UrlAccess` | 真偽値 | `false` | URL アクセスを記録する |
| `Browsing` | 真偽値 | `false` | ページの閲覧を記録する |
| `Upload` | 真偽値 | `false` | アップロードを記録する |
| `Download` | 真偽値 | `false` | ダウンロードを記録する |
| `Print` | 真偽値 | `false` | 印刷を記録する |
| `LocalFile.Enabled` | 真偽値 | `false` | この端末上のファイルに記録する |
| `LocalFile.Directory` | 文字列 | `""` | 保存先。空欄の場合は `%LocalAppData%\BrowserGuard\netlog`。パスマクロを展開する |
| `LocalFile.MaxDays` | 数値 | `30` | 日ごとのファイルを保持する日数。`0` は無制限 |
| `LocalFile.MaxSizeMB` | 数値 | `0` | 1 日あたりのファイルの上限。超えた分は分割する。`0` は分割しない |
| `Sender.Enabled` | 真偽値 | `false` | 収集サーバーへ送信する |
| `Sender.Endpoint` | 文字列 | `""` | 送信先の URL。空欄の場合は送信しない |
| `Sender.Spool.Enabled` | 真偽値 | `false` | 送信できなかったエントリを保留する |
| `Sender.Spool.MaxSizeMB` | 数値 | `10` | 保留ファイルの上限。超えた分は捨てる。`0` は無制限 |
| `Sender.Spool.Retry.Enabled` | 真偽値 | `true` | 保留したエントリを再送する |
| `Sender.Spool.Retry.IntervalMinutes` | 数値 | `5` | 再送を試みる間隔（分） |

■ **`UrlAccess` はページ内のすべての要求を記録します。**
  画像・スクリプト・スタイルシート・API 呼び出しなども対象となるため、
  ページを 1 枚開くだけで数十から数百のエントリが発生します。
  「どのサイトを見たか」を記録する目的であれば、`Browsing` を使用してください。
  `Browsing` はページの遷移が完了したときに 1 件だけ記録します。

■ `Sender` を有効にしても `Spool` を無効にした場合、
  収集サーバーが応答しない間のエントリは失われます。
  証跡として確実に集約する必要がある場合は、`Spool` も有効にしてください。

\newpage

## アップロード制御（UploadGuard）

アップロードしてよいローカルファイルを、拡張子とパスで絞り込みます。

```json
"UploadGuard": {
  "Enabled": true,
  "BlockedExtensions": [".exe", ".bat", ".cmd", ".js", ".vbs"],
  "AllowedExtensions": [],
  "BlockedPaths": ["\\\\Confidential\\\\"],
  "AllowedPaths": ["^C:\\\\Users\\\\[^\\\\]+\\\\Documents\\\\"]
}
```

| パラメータ | データ型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `Enabled` | 真偽値 | `false` | この機能を有効にする |
| `BlockedExtensions` | 文字列の配列 | `[".exe", ".bat", ".cmd", ".js", ".vbs"]` | アップロードを禁止する拡張子 |
| `AllowedExtensions` | 文字列の配列 | `[]` | アップロードを許可する拡張子 |
| `BlockedPaths` | 文字列の配列 | `[]` | アップロードを禁止するパス（正規表現） |
| `AllowedPaths` | 文字列の配列 | `[]` | アップロードを許可するパス（正規表現） |

判定は以下の順に行われ、最初に該当した理由でアップロードを中止します。

1. `BlockedPaths` に一致する → 「アップロードが禁止された場所のファイルです」
2. `BlockedExtensions` に一致する → 「禁止された拡張子です」
3. `AllowedPaths` が空でなく、いずれにも一致しない → 「アップロードが許可されていない場所のファイルです」
4. `AllowedExtensions` が空でなく、いずれにも一致しない → 「許可された拡張子ではありません」

* 禁止の一覧が先に判定されるため、両方に該当する場合は禁止が優先されます。
* 許可の一覧が空の場合、その条件では絞り込みません。
* 拡張子は前方一致ではなく、ファイル名の末尾との一致で判定します。大文字・小文字は区別しません。
* パスはファイルのフルパスに対する正規表現です。大文字・小文字は区別しません。

■ JSON の文字列では `\` を `\\` と書きます。
  正規表現としての `\\`（`\` 1 文字）を表すには、JSON 上では `\\\\` と 4 つ重ねます。

■ 解釈できない正規表現は、その 1 件だけが無視されます。
  1 件の記述誤りによって一覧全体が「すべてに一致」または「何にも一致しない」に
  変わることはありません。

### ブロック時の動作

* 画面遷移を伴うアップロード（フォームの送信）の場合、直前のページに戻します。
* それ以外（スクリプトによる背後での送信など）の場合、要求そのものを中止します。
* 警告ダイアログを表示します。
* 監査ログが有効な場合、`upload-guard` として記録します。

■ ブロックされたアップロードについては、
  「アップロードファイルの控え」による複製は行われません。
  端末から出ていないファイルを証跡として残さないためです。

\newpage

## 設定ページの遮断（SettingPageFilter）

ブラウザーの設定ページを開けなくします。

```json
"SettingPageFilter": {
  "Enabled": true,
  "NotifyOnBlocked": true,
  "BlockedPrefixes": [
    "edge://settings",
    "edge://extensions",
    "edge://flags",
    "edge://policy"
  ]
}
```

| パラメータ | データ型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `Enabled` | 真偽値 | `false` | この機能を有効にする |
| `NotifyOnBlocked` | 真偽値 | `false` | ブロック時に警告ダイアログを表示する |
| `BlockedPrefixes` | 文字列の配列 | `["edge://settings", "edge://flags", "edge://policy"]` | ブロックする URL（前方一致） |

* 一覧の文字列で前方一致した URL が対象です。
* ブロックされたタブは直前のページに戻ります。
  戻り先がない場合は `about:blank` を表示します。

■ 判定はページの遷移が確定した後に行われます。
  ブラウザー自身のページは遷移前に中止できないためです。
  そのため、ブロックされるページが一瞬表示されることがあります。

■ `edge://extensions` を遮断すると、
  「拡張機能の更新が反映されない場合」に記載した手動更新の操作も行えなくなります。
  運用に合わせて含めるかどうかを判断してください。

## 起動時プログラム実行（StartupLauncher）

ブラウザーの起動に合わせて、指定されたプログラムを実行します。

```json
"StartupLauncher": {
  "Enabled": true,
  "Programs": [
    {
      "Path": "C:\\Program Files\\Audit\\AuditAgent.exe",
      "Arguments": ["--mode", "browser"],
      "WorkingDirectory": "C:\\Program Files\\Audit",
      "EnvironmentVariables": { "AUDIT_SOURCE": "browserguard" },
      "Sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
    }
  ]
}
```

| パラメータ | データ型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `Enabled` | 真偽値 | `false` | この機能を有効にする |
| `Programs` | オブジェクトの配列 | `[]` | 実行するプログラムの一覧 |
| `Programs[].Path` | 文字列 | `""` | 実行ファイルのパス |
| `Programs[].Arguments` | 文字列の配列 | `[]` | 引数。1 要素が 1 つの引数 |
| `Programs[].WorkingDirectory` | 文字列 | `""` | 作業ディレクトリ。空欄の場合は実行ファイルのあるディレクトリ |
| `Programs[].EnvironmentVariables` | オブジェクト | `{}` | 追加する環境変数（`"名前": "値"`） |
| `Programs[].Sha256` | 文字列 | `""` | 実行ファイルの SHA-256。空欄の場合は照合しない |

* プログラムはログオンしているユーザーの権限で実行されます。
* 実行に失敗したプログラムがあっても、残りのプログラムは実行されます。
  失敗した内容はホストのログに記録されます。

■ **`Path` にはパスマクロも環境変数も適用されません。記述したパスがそのまま使われます。**
  環境変数はブラウザーを動かしているユーザー自身が変更可能であるため、
  パスマクロや環境変数を展開すると、任意のファイルを実行することが可能となってしまうためです。

■ `Sha256` を指定すると、実行前にハッシュを照合し、
  一致しない場合は実行しません。空欄の場合は照合しません。
  実行ファイルの差し替えを検知する必要がある場合は指定してください。

\newpage

## 使用時間の制限（UsageTimeLimit）

連続して使用できる時間と、使用を許可する時間帯を制限します。

```json
"UsageTimeLimit": {
  "Enabled": true,
  "MaxContinuousMinutes": 120,
  "AllowedTimeRanges": [
    { "Start": "09:00", "End": "12:00" },
    { "Start": "13:00", "End": "18:00" }
  ],
  "OnExceeded": {
    "Action": "WarnOnly",
    "GraceSeconds": 60,
    "ReWarnIntervalMinutes": 10
  }
}
```

| パラメータ | データ型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `Enabled` | 真偽値 | `false` | この機能を有効にする |
| `MaxContinuousMinutes` | 数値 | `0` | 連続して使用できる時間（分）。`0` は無制限 |
| `AllowedTimeRanges` | オブジェクトの配列 | `[]` | 使用を許可する時間帯。空の場合は時間帯では制限しない |
| `AllowedTimeRanges[].Start` | 文字列 | `""` | 開始時刻（`HH:mm`、24 時間表記の現地時刻） |
| `AllowedTimeRanges[].End` | 文字列 | `""` | 終了時刻（`HH:mm`、24 時間表記の現地時刻） |
| `OnExceeded.Action` | 文字列 | `"WarnOnly"` | 超過時の動作。`WarnOnly` または `Terminate` |
| `OnExceeded.GraceSeconds` | 数値 | `60` | `Terminate` の場合に、警告してから終了するまでの猶予（秒） |
| `OnExceeded.ReWarnIntervalMinutes` | 数値 | `10` | 警告を出し直す間隔（分）。`0` の場合は繰り返さない |

### 時間帯の指定

* 終了が開始より**前**である場合、日をまたぐ指定と解釈されます。
  `{ "Start": "22:00", "End": "02:00" }` は日をまたぐ 4 時間の時間帯です。
* 開始と終了が同じ場合は、終日を表します。
* `HH:mm` として読み取れない時間帯は無視されます。

### 超過時の動作

* `Action` の値は大文字・小文字を区別しません。
  `WarnOnly` でも `Terminate` でもない値が指定された場合、既定の `WarnOnly` のままとなります。
  綴り誤りによって意図せずブラウザーが終了することを防ぐためです。
* `Terminate` の場合、まず警告ダイアログを表示し、
  `GraceSeconds` の経過後にすべてのウィンドウを閉じます。
  ダイアログを閉じなかった場合でも、時刻になれば終了します。
* 連続使用時間は、ブラウザーを起動してからの経過時間で数えます。
  ブラウザーを再起動すると、そこから数え直しになります。

■ 連続使用時間の判定は 1 分ごとに行われます。
  上限を超えてから警告が表示されるまで、最大で 1 分程度の間隔があります。

\newpage

## タブ数の上限（TabCountLimit）

同時に開けるタブの数を制限します。

```json
"TabCountLimit": {
  "Enabled": true,
  "MaxCount": 20
}
```

| パラメータ | データ型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `Enabled` | 真偽値 | `false` | この機能を有効にする |
| `MaxCount` | 数値 | `0` | 同時に開けるタブの数。`0` は無制限 |

* タブはすべてのウィンドウをまたいで数えます。
  別のウィンドウを開いても回避できません。
* 上限を超えた場合、新しく開かれたものから順に自動的に閉じ、警告ダイアログを表示します。
* 前回のセッションが復元された場合も、上限まで減らされます。

■ `MaxCount` が `0` の場合は無制限です。
  設定の書き忘れによって、すべてのタブが閉じられることはありません。

\newpage

## アップロードファイルの控え（UploadFileBridge）

アップロードされたファイルの控えを、指定の場所に複製します。

```json
"UploadFileBridge": {
  "Enabled": true,
  "Destination": "\\\\fileserver\\BrowserGuardAudit\\%MACHINENAME%\\%USER%\\%DATE%",
  "MaxSizeMB": 100,
  "BlockedExtensions": [".tmp", ".log"],
  "AllowedExtensions": [],
  "BlockedUrls": [],
  "AllowedUrls": []
}
```

| パラメータ | データ型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `Enabled` | 真偽値 | `false` | この機能を有効にする |
| `Destination` | 文字列 | `""` | 控えの保存先。パスマクロを展開する。空欄の場合は複製しない |
| `MaxSizeMB` | 数値 | `0` | 控えを残すファイルの上限。超える場合は複製しない。`0` は無制限 |
| `BlockedExtensions` | 文字列の配列 | `[]` | 控えを残さない拡張子 |
| `AllowedExtensions` | 文字列の配列 | `[]` | 控えを残す拡張子 |
| `BlockedUrls` | 文字列の配列 | `[]` | 控えを残さないアップロード先（正規表現） |
| `AllowedUrls` | 文字列の配列 | `[]` | 控えを残すアップロード先（正規表現） |

* 一覧の読み方はアップロード制御と同じです。
  禁止の一覧が先に判定され、許可の一覧が空の場合はその条件では絞り込みません。
* 判定は「アップロード先の URL」→「拡張子」→「サイズ」の順に行われます。
* 保存先に同名のファイルがある場合、`report.xlsx` に続けて `report_2.xlsx` のように
  連番が付きます。既存のファイルを上書きすることはありません。

■ ファイルサーバー上にファイルを転送することも可能です。
  ただし、複製はログオンしているユーザーの権限で行われるため、そのユーザーが書き込める場所を指定してください。

■ 控えを残せなかった場合、その理由が `upload-file-bridge` として監査ログに記録されます。
  アップロード自体は成立しているため、記録がないと証跡に説明のつかない欠落が生じるためです。
  複製に成功した場合は、監査ログには記録されません（ホストのログには記録されます）。

■ 既定では `BlockedExtensions` も `AllowedExtensions` も空であり、
  アップロードされたすべてのファイルが複製の対象になります。
  保存先の容量に注意してください。

## パスマクロ

以下のパラメータでは、パスの中でマクロと環境変数を使用できます。

* `NetLogger.LocalFile.Directory`
* `UploadFileBridge.Destination`

| マクロ | 展開される内容 |
| --- | --- |
| `%MACHINENAME%` | コンピューター名 |
| `%USER%` | ログオンしているユーザー名 |
| `%DATE%` | 日付（`YYYY-MM-DD`） |
| `%YYYY%` | 年（4 桁） |
| `%MM%` | 月（2 桁） |
| `%DD%` | 日（2 桁） |

* マクロを展開した後、Windows の環境変数（`%LOCALAPPDATA%` など）が展開されます。
* いずれにも該当しない名前は、記述したまま残ります。

■ `%MACHINENAME%` と `%USER%` は、環境変数ではなく OS から直接取得した値です。
  環境変数の `%COMPUTERNAME%` や `%USERNAME%` はユーザー自身が変更できるため、
  証跡を別の名前で保存されることを避ける目的で、これらを用意しています。

# 監査ログの書式

## 出力先とファイル名

`NetLogger.LocalFile` を有効にした場合、保存先に以下のファイルが作られます。

| ファイル | 内容 |
| --- | --- |
| `netlog.jsonl` | 当日のエントリ |
| `netlog_YYYY-MM-DD.jsonl` | 過去の日のエントリ |
| `netlog_YYYY-MM-DD_N.jsonl` | Nは2以上の整数。同じ日で `MaxSizeMB` を超えて分割された 2 つ目以降（過去世代）。 |
| `netlog-pending.jsonl` | 収集サーバーへ送信できず保留しているエントリ |
| `netlog-pending.taken.jsonl` | 再送の処理中に一時的に作られるファイル |

* 日付が変わった後の最初のエントリで、当日分が `netlog_YYYY-MM-DD.jsonl` として切り替わります。
  ブラウザーが動作していない間に日付が変わった場合も、次のエントリで切り替わります。
* `MaxDays` を過ぎた `netlog_YYYY-MM-DD.jsonl` は削除されます。
  保存先にある BrowserGuard 以外のファイルには影響しません。
* 形式は JSON Lines（1 行に 1 つの JSON オブジェクト）です。
  文字エンコーディングは UTF-8（BOM なし）です。
* 日本語のページタイトルなどは、`\uXXXX` に変換せずそのまま記録されます。

## エントリの共通フィールド

すべてのエントリに以下のフィールドが含まれます。

| フィールド | 内容 |
| --- | --- |
| `operation` | 操作の種類 |
| `name` | 操作の対象（ページタイトル、ファイル名、ホスト名など） |
| `url` | 対象の URL |
| `timestamp` | 発生日時（`YYYY-MM-DD HH:mm:ss`、現地時刻） |
| `host` | コンピューター名 |
| `user` | `ドメイン\ユーザー名` |
| `user_displayName` | ユーザーの表示名。取得できない場合は出力されません |
| `session` | Windows のセッション ID |

■ `host`、`user`、`user_displayName`、`session` は、
  拡張機能が何を送ってきたかによらず、ホストが付け直します。
  記録した場所と主体を確実に特定できるのはホスト側だけであるためです。

## operation ごとのフィールド

| `operation` | 記録される契機 | `name` | 追加のフィールド |
| --- | --- | --- | --- |
| `urlaccess` | http/https の要求ごと | ホスト名 | |
| `browsing` | ページの遷移完了ごと | ページタイトル | |
| `upload` | ファイルを含む要求ごと | ファイル名 | |
| `download` | ダウンロードの完了ごと | 保存先のフルパス | |
| `print` | 印刷の開始ごと | ページタイトル | |
| `upload-guard` | アップロードを中止したとき | ファイルのパス | `reason`（中止した理由） |
| `upload-file-bridge` | 控えを残せなかったとき | ファイルのパス | `reason`（残せなかった理由） |

■ `upload-guard` と `upload-file-bridge` は、`Upload` の設定によらず、
  監査ログが有効であれば記録されます。
  通常の閲覧ではなく、拒否または失敗した操作の記録であるためです。

### 記録例

```json
{"operation":"browsing","name":"社内ポータル","url":"https://portal.example.jp/","timestamp":"2026-09-07 10:12:33","host":"PC-0123","user":"EXAMPLE\\taro","user_displayName":"山田 太郎","session":1}
{"operation":"upload-guard","name":"C:\\Users\\taro\\Desktop\\tool.exe","url":"https://example.com/upload","timestamp":"2026-09-07 10:15:02","reason":"禁止された拡張子です","host":"PC-0123","user":"EXAMPLE\\taro","session":1}
```

\newpage

## 収集サーバーへの送信

`NetLogger.Sender` を有効にした場合、エントリは以下の形で送信されます。

* `Endpoint` に対する HTTP POST
* `Content-Type: application/json`
* 本文は 1 エントリ分の JSON オブジェクト 1 つ（UTF-8）

収集サーバー側は、HTTP のステータスコードで成否を返してください。
2xx を成功として扱い、それ以外は失敗として扱います。

■ エントリは 1 件ずつ送信されます。まとめて送る形式ではありません。

## 保留（スプール）と再送

収集サーバーが受け取らなかったエントリは、`Spool` が有効な場合、
監査ログと同じフォルダーの `netlog-pending.jsonl` に保留されます。

* 一度失敗した後は、以降のエントリは送信を試みずに直接保留されます。
  応答しない収集サーバーに対して、エントリごとに待ち時間が発生することを避けるためです。
* `Retry` が有効な場合、`IntervalMinutes` の間隔で保留分の送信が再試行されます。
  収集サーバーが復旧したことは、この再試行によって検知されます。
* 保留ファイルが `MaxSizeMB` に達すると、それ以降のエントリは失われます。

■ 再送の途中でブラウザーが終了した場合、
  処理中だったエントリが次回に再度送信されることがあります。
  監査ログにおいては、重複よりも欠落を避けることを優先しています。
  収集サーバー側では、同一のエントリが複数回届きうるものとして扱ってください。

■ `Spool` を無効にした場合、送信できなかったエントリはその場で失われます。
  `Retry` を無効にした場合、保留されたエントリは自動では送信されず、
  `netlog-pending.jsonl` から手作業で回収する必要があります。

# ログとトラブルシューティング

## ホストのログ

ネイティブメッセージングホストの動作は、以下に記録されます。

```
%APPDATA%\BrowserGuard\BrowserGuard.log
```

* 10 MB を超えると `BrowserGuard_1.log` 以降へ退避し、最大 10 世代を保持します。
* 設定の読み込み、警告ダイアログの表示、ファイルの複製、
  プログラムの実行とその失敗が記録されます。
* 監査ログのエントリは、件数が多いため個別には記録されません。

まず確認すべき内容は以下の通りです。

| 記録されている内容 | 意味 |
| --- | --- |
| `Command: load config` | 拡張機能がホストと通信し、設定を読み込んだ |
| `Command: log entry, writing to ...` | 監査ログの保存先が決まった |
| `Command: log entry, but logging is disabled` | 監査ログが無効になっている |
| `UploadFileBridge: copied ... to ...` | 控えの複製に成功した |
| `UploadFileBridge: no copy kept of ...` | 控えを残さなかった。理由が続けて記録される |
| `StartupLauncher: ...` | 起動時プログラムの実行に失敗した |

■ ファイルそのものが作られない場合、拡張機能がホストを起動できていません。
  ネイティブメッセージングホストの登録（レジストリとホストマニフェスト）と、
  ホストマニフェストの `allowed_origins` に記載された拡張機能 ID が
  実際にインストールされた ID と一致しているかを確認してください。

## 拡張機能のログ

ポリシーで強制インストールされた拡張機能は、既定では開発者ツールを開けません。
拡張機能側のログは、Edge のログから確認します。

1. Edge のプロセスを完全に終了します。

```
taskkill /F /IM msedge.exe /T
```

2. ログを有効にして Edge を起動します。

```
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --enable-logging --v=1
```

3. 以下にログが出力されます。

```
%LocalAppData%\Microsoft\Edge\User Data\chrome_debug.log
```

■ `chrome_debug.log` は Edge の起動ごとに作り直されます。前回起動時の内容は残りません。

■ 手順 1 を省略すると、前回のプロセスが残っていてログが出力されないことがあります。

# FAQ（よくある質問）

## インストールしましたが、拡張機能がインストールされません

crx を配置しただけでは Edge は拡張機能をインストールしません。
Edge のポリシー `ExtensionSettings` への登録が別途必要です。
`edge://policy` を開き、`ExtensionSettings` に BrowserGuard の項目が
含まれているかを確認してください。

登録手順は「拡張機能の登録」または「拡張機能のポリシー登録」をご参照ください。

## 設定ファイルを書き換えましたが、動作が変わりません

以下の順に確認してください。

1. 書き換えたファイルが、レジストリ `HKLM\SOFTWARE\BrowserGuard` の
   `Configfile` が指すファイルであること。
   インストール先を変更した場合、想定と異なるパスを指していることがあります。
2. Edge を再起動したこと。
   設定は拡張機能のサービスワーカーが起動したときに読み込まれます。
3. ホストのログに `Command: load config` の行が新たに記録されていること。
4. JSON として壊れていないこと。
   壊れている場合、ホストはエラーを返し、いずれの機能も動作しません。

## グループポリシーで設定したはずのポリシーが反映されていません

グループポリシーで `ExtensionSettings` が構成されている環境では、
`gpupdate` のたびにグループポリシー側の値で上書きされます。
インストーラーのタスクや `reg` コマンドでレジストリに直接書き込んだ内容は失われます。

実際に適用されている内容は `edge://policy` で確認してください。
`gpedit.msc` はグループポリシーが配信した内容のみを表示するため、
レジストリに直接書き込んだ内容は表示されません。

## 監査ログが出力されません

以下をすべて満たしているかを確認してください。

* `NetLogger.Enabled` が `true` であること。
* `LocalFile.Enabled` または `Sender.Enabled` のいずれかが `true` であること。
  両方が `false` の場合、記録先がないため何も記録されません。
* 記録したい操作に対応する項目（`Browsing`、`Upload` など）が `true` であること。
* 保存先が、ログオンしているユーザーが書き込める場所であること。

ホストのログに `Command: log entry, but logging is disabled` と記録されている場合は、
`NetLogger.Enabled` が `false` です。

## 監査ログが大量に出力されます

`UrlAccess` が有効になっている可能性があります。
`UrlAccess` は画像やスクリプトを含むすべての要求を記録するため、
ページを 1 枚開くだけで数十から数百のエントリが発生します。

「どのサイトを見たか」の記録が目的であれば、`UrlAccess` を無効にし、
`Browsing` を有効にしてください。

## 収集サーバーにログが届きません

* `Sender.Endpoint` が設定されているかを確認してください。
  空欄の場合、`Sender.Enabled` が `true` でも送信は行われません。
* 保存先に `netlog-pending.jsonl` があるかを確認してください。
  存在する場合、収集サーバーに届かなかったエントリが保留されています。
* 収集サーバーが 2xx を返しているかを確認してください。
  それ以外のステータスコードは失敗として扱われます。

## アップロードがブロックされる／されない

ブロックの判定順は「設定ファイルの書式」の
「アップロード制御（UploadGuard）」をご参照ください。
特に以下にご注意ください。

* 禁止の一覧が先に判定されるため、両方に該当する場合は禁止が優先されます。
* 許可の一覧が空の場合、その条件では絞り込みません。
  `AllowedExtensions` を空のままにして「許可した拡張子だけを通す」ことはできません。
* パスの一覧は正規表現です。JSON 上では `\` を `\\\\` と 4 つ重ねて記述します。
  記述を誤った正規表現は、その 1 件だけが無視されます。

## ユーザーが設定を変更できないようにしたい

BrowserGuard にはユーザーが設定を変更するための画面がないため、
設定画面から変更されることはありません。

ただし、インストーラーはインストール先フォルダーに `Users` の変更権限を付与するため、
既定では一般ユーザーが設定ファイルを直接書き換えることができます。
「設定ファイルの保護」の手順でアクセス権を制限してください。

## アンインストールしたのに監査ログが残っています

監査ログとアップロードファイルの控えは証跡であるため、
製品を削除しても意図的に残されます。不要な場合は別途削除してください。

# 制限事項

## 設定の反映

設定は拡張機能のサービスワーカーが起動したときに読み込まれます。
サービスワーカーは待機状態からの復帰のたびに読み直すため、
多くの場合は Edge の再起動なしでも反映されますが、反映の時期は保証されません。
確実に反映させるには Edge を再起動してください。

## 対応ブラウザー

Microsoft Edge（Chromium 版）のみに対応しています。
他のブラウザーには対応していません。

## 設定ページの遮断

ブラウザー自身のページは、遷移が確定する前に中止できません。
そのため、遮断されるページが一瞬表示されてから前のページに戻ります。

## 使用時間の制限

連続使用時間の判定は 1 分ごとに行われます。
上限を超えてから警告が表示されるまで、最大で 1 分程度の間隔があります。

また、連続使用時間はブラウザーを起動してからの経過時間で数えるため、
ブラウザーを終了して起動し直すと、そこから数え直しになります。

## 監査ログの重複

収集サーバーへの再送の途中でブラウザーが終了した場合、
処理中だったエントリが次回に再度送信されることがあります。
収集サーバー側では、同一のエントリが複数回届きうるものとして扱ってください。

## MSI パッケージの構成

MSI パッケージは、インストーラーの exe を内包してサイレント実行する形式です。
MSI 単体ですべてのファイルを配置しているわけではありません。

そのため、以下の点が通常の MSI と異なります。

* インストール時に一時フォルダーへ exe を展開して実行するため、
  完了までに通常の MSI より時間がかかります。
* 個々のファイルは MSI の管理対象ではないため、修復（`msiexec /f`）を行っても
  ファイルは復元されません。再インストールしてください。
* インストール先のフォルダーを MSI のプロパティで変更することはできません。
